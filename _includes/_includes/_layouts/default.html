Unit 1 — Database Management System

1.1 Data, Information and the Idea of a Database

Every system that stores records faces the same problem. Information arrives in pieces, and those pieces need to be kept in a form that can be found again, changed when necessary, and protected from confusion. A school knows this well. Names arrive on admission forms, marks arrive after each exam, fees arrive monthly. If each of these lives in a separate paper file, answering a simple question like "which students in Class 10 have not paid this month's fee" requires opening three files and comparing them by hand.

A database solves this by storing related facts together in an organised structure. The facts themselves, taken individually and without context, are called data. A row of numbers like 2082, 95, Binay means nothing on its own. Once those numbers are arranged and interpreted, they become information: Binay scored 95 marks in the year 2082 and is one of the top performers.

Concept cracker. Data is the raw material; information is the finished product. Processing is what turns one into the other. If your answer to "what is the difference between data and information" mentions context or meaning, you have the mark.

A database is an organised collection of related data that can be stored, searched, updated and retrieved efficiently. In modern practice, databases are held on computers, though the idea long predates them. A library catalogue, a hospital register, a telephone directory are all databases in the ordinary sense. What makes computerised databases powerful is speed and scale: they can search millions of rows in less time than it takes to blink.

Why paper files and spreadsheets eventually fail

Before computerised databases, records were kept in traditional file systems: paper registers or simple digital files, one file per purpose. These work at small scale but break down in three predictable ways.

  • Duplication. The same student's name and address are written again and again in the admission file, the fees file, the exam file. If the address changes, it must be updated everywhere, and any file missed becomes wrong.
  • Inconsistency. Once duplicates exist, they drift apart. The fees file says one address, the exam file another. No one knows which is correct.
  • Difficulty of searching across files. A question that spans two files requires manual comparison. At scale this becomes impossible.

Tutor's tip. When you are asked in an exam to justify a database over a spreadsheet, do not simply say "a database is better". Name the specific problem it removes. Duplication, inconsistency and the cost of cross-file searching are the three safe answers, and one example of each is enough for full marks.

1.2 Database Management System (DBMS)

A database by itself is just stored facts. To use those facts, something must sit between the user and the storage and translate requests into action. That something is the Database Management System.

A DBMS is software that allows users to create, store, retrieve, update and delete data in a structured way while enforcing rules about who may do what. It is the layer that makes a database safe, consistent and usable. Common examples are MySQL, Oracle Database, Microsoft SQL Server, PostgreSQL, MongoDB and SQLite.

Concept cracker. Think of a library. The books are the database. The librarian who knows the catalogue, checks your membership, and fetches the right book is the DBMS. You never walk into the shelves yourself; you ask the librarian, and the librarian enforces the rules.

What a DBMS does

  1. Data storage. Holds data in tables of rows and columns.
  2. Data retrieval. Finds rows quickly using simple commands.
  3. Data manipulation. Supports inserting new rows, updating existing ones and deleting unwanted ones.
  4. Data integrity. Enforces rules so that only valid data is accepted. A phone number field will not accept letters.
  5. Redundancy control. Minimises duplication by centralising storage and encouraging normalisation.
  6. Security. Controls who may see or change what.
  7. Backup and recovery. Keeps data safe and restorable after failure.
  8. Concurrent access. Allows many users to work at the same time without corrupting each other's changes.

Advantages of a DBMS

  • Greatly reduced duplication and inconsistency.
  • Fast retrieval even from very large stores.
  • Centralised control of security and access.
  • Backup and recovery are built in.
  • Multiple users and applications can share the same data.
  • Integrity rules are enforced automatically rather than by hand.

Disadvantages of a DBMS

  • Setup and licensing cost, especially for commercial systems.
  • Requires trained staff to design, tune and maintain.
  • Complex systems need regular maintenance and monitoring.
  • Performance can degrade with extremely large datasets if poorly designed.
  • If the system fails and backups are poor, the whole organisation may lose access at once.

Tutor's tip. In five-mark questions on advantages and disadvantages, quality beats quantity. Name three advantages and three disadvantages, each with one sentence of explanation. Do not list ten points with no explanation; examiners award marks for reasoning, not for volume.

1.3 Relational Database Management System (RDBMS)

An RDBMS is a DBMS that stores data in tables and links those tables using shared fields called keys. The word relational does not mean "related" in the everyday sense; it means the data is arranged in relations, which is the formal term for tables.

What makes an RDBMS special is that a fact is stored once and referred to elsewhere by key. A student's name lives in the Students table. The Library table does not repeat the name; it stores the student's ID, which points back to the Students table. Change the name in one place and every reference sees the new value.

MySQL, Oracle, PostgreSQL and Microsoft SQL Server are all RDBMSs. MySQL is the example used throughout this unit.

1.4 Tables, Fields and Records

A table is the basic container of an RDBMS. It organises data into rows and columns, each column holding one kind of fact and each row holding one complete entry.

StudentID Name Class DateOfBirth
101Binay Adhikari102010-03-12
102Subigya Nepal102011-07-25
103Aarambha Gharti92013-11-10

A field is a column. StudentID, Name, Class and DateOfBirth are the four fields of this table. Each field is defined to hold one type of data: StudentID holds numbers, Name holds text, DateOfBirth holds dates.

A record is a row. The row containing 101, Binay Adhikari, 10 and 2010-03-12 is one record: the complete information about one student.

Concept cracker. Fields run vertically and describe what kind of fact is being stored. Records run horizontally and describe one instance of that fact. If you can point at a column and say what it holds, that column is a field. If you can point at a row and say whose data it is, that row is a record.

1.5 Keys

Keys are columns used to identify rows uniquely and to link tables together. Three kinds matter for Grade 10.

Primary key

A primary key is a field, or combination of fields, that uniquely identifies every record in a table. It cannot be repeated and it cannot be empty. In the Students table above, StudentID is the primary key.

Rules of a primary key:

  • Every value must be unique across the table.
  • No value may be NULL.
  • Each table may have only one primary key.

Foreign key

A foreign key is a field in one table that refers to the primary key of another table. It creates the link between the two tables and ensures that only valid references are entered.

Consider a Library table that records which student borrowed which book.

BookIDBookTitleStudentID (Foreign Key)
B_01Nepali History201
B_02Database Basics201
B_03Learn Python202

Here StudentID is a foreign key pointing to the StudentID primary key of the Students table. If someone tries to record a loan to student 999 who does not exist, the database refuses the entry. This is how integrity is preserved across tables.

Composite key

A composite key is a key made of two or more fields combined, used when no single field is unique on its own.

StudentIDSubjectMarks
301Nepali85
301Social92
302Computer95

Neither StudentID nor Subject alone identifies a row, because student 301 appears twice and subject Nepali appears once but could appear again. The combination of StudentID and Subject is unique, so together they form a composite key.

Tutor's tip. When asked to identify a primary key in a table, look for the field whose value would never repeat and would never be blank. Name is a poor primary key because two students may share a name. Date of birth is a poor primary key because two students may share a birthday. A roll number or student ID is almost always the right answer.

1.6 Data Types in SQL

Every column in a table is declared with a data type. The data type tells the database what kind of value the column may hold and how much space to reserve. Choosing correctly prevents errors and saves space.

Numeric types

SMALLINTWhole numbers with a smaller range.

DECIMAL(p, s)Exact numbers with decimal points. \(p\) is the total number of digits and \(s\) the number after the decimal.

Character types

The difference between CHAR and VARCHAR matters. CHAR(10) always stores ten characters, padding with spaces if the value is shorter. VARCHAR(10) stores only as many characters as are actually entered, up to ten. For names of varying length, VARCHAR is the better choice.

Tutor's tip. When you write a CREATE TABLE statement, decide the data type by asking what the column will hold. A phone number looks numeric but should be VARCHAR, because it may begin with a zero and is never used in arithmetic. A roll number is INT because it is used in arithmetic and comparison. These two choices catch many students.

1.7 SQL Constraints

Constraints are rules attached to columns that restrict what values may be entered. They protect data integrity by rejecting anything that violates the rule.

ConstraintEffect
PRIMARY KEYUniquely identifies each row. No duplicates, no NULLs.
FOREIGN KEYLinks a column to the primary key of another table.
NOT NULLForbids empty values in the column.
UNIQUEEnsures all values in the column are different from each other.
CHECKLimits values to those satisfying a condition.
DEFAULTSupplies a value automatically when none is given.

Constraints matter because they stop bad data at the gate. If a column is declared NOT NULL, the database refuses to save a row without a value there. If a column has a CHECK constraint limiting marks to between 0 and 100, an attempt to enter 150 fails immediately. Without constraints, the same errors would be caught much later, if at all.

1.8 SQL and Its Sublanguages

SQL, pronounced "sequel", stands for Structured Query Language. It was developed at IBM in the 1970s and is the standard language for communicating with relational databases. A query is simply a request sent to the database, written in SQL.

SQL is divided into sublanguages according to what they do.

DDL — Data Definition Language

DDL statements define and change the structure of the database: its tables, columns and constraints. DDL commands are committed automatically; once executed, the change is permanent and cannot be rolled back.

CommandPurpose
CREATECreates a new database, table, view or index.
ALTERChanges the structure of an existing table, for example adds a column.
DROPDeletes a database object permanently, including its data.
TRUNCATERemoves all rows from a table but keeps the structure.
RENAMEChanges the name of a table or column.

DML — Data Manipulation Language

DML statements work on the data inside the tables, not on the structure. DML changes can be rolled back unless committed.

CommandPurpose
INSERTAdds new rows.
SELECTRetrieves rows.
UPDATEModifies existing rows.
DELETERemoves rows.

Concept cracker. DDL changes the shape of the container. DML changes what is inside the container. If the command would still make sense on an empty table, it is DDL. If it needs rows to do anything, it is DML.

The critical difference between DELETE and TRUNCATE

Both remove rows, but they are not the same.

  • DELETE removes selected rows according to a WHERE condition. It can be rolled back. It fires any triggers attached to the table. It is slower on large tables because it logs each row individually.
  • TRUNCATE removes all rows in one operation, ignoring any condition. It cannot be rolled back in most databases. It does not fire triggers. It is much faster on large tables.

If the question says "remove some rows", the answer is DELETE. If it says "remove all rows but keep the table structure", the answer is TRUNCATE.

1.9 Basic SQL Statements

Creating a database and using it

CREATE DATABASE school;
USE school;

The first statement creates an empty database named school. The second selects it so that subsequent statements work inside it.

Creating a table

CREATE TABLE students (
    ID INT PRIMARY KEY,
    Name VARCHAR(50),
    Class INT NOT NULL,
    DOB DATE
);

This creates a table with four columns. ID is the primary key. Class cannot be empty. The other two accept values of the stated types.

Inserting rows

INSERT INTO students (ID, Name, Class, DOB)
VALUES (1, 'Dikshya Pokhrel', 10, '2007-11-13');

Retrieving rows

SELECT * FROM students;
SELECT Name, Class FROM students;
SELECT Name, DOB FROM students WHERE Class = 10;

The asterisk means all columns. Naming columns retrieves only those columns. The WHERE clause filters rows to those satisfying the condition.

Updating rows

UPDATE students
SET Class = 11
WHERE ID = 5;

The WHERE clause is essential. Without it, the update would apply to every row in the table, which is almost never what is intended.

Deleting rows

DELETE FROM students WHERE Name = 'Biraj';

Again the WHERE clause decides which rows are removed. Without it, every row is deleted.

Tutor's tip. Two habits prevent most SQL mistakes. First, always write the WHERE clause before running an UPDATE or DELETE, even in your head, and check that it selects only the rows you intend to change. Second, when a question asks you to change data, ask yourself whether you are changing the structure or the contents. Changing the structure means ALTER, changing contents means UPDATE.

1.10 The WHERE and LIKE Clauses

The WHERE clause filters rows by a condition. Without it, a SELECT returns every row in the table.

SELECT Name, DOB FROM students WHERE Class = 10;

The LIKE clause filters by pattern rather than exact value. It uses two wildcards.

  • % matches any sequence of characters, including none.
  • _ matches exactly one character.
SELECT Name, Class FROM students WHERE Name LIKE 'A%';
-- matches names beginning with A

UPDATE students SET Class = 12 WHERE Name LIKE '_man';
-- matches names of four letters ending in "man", such as Aman

DELETE FROM students WHERE Name LIKE '%esh';
-- matches names ending in "esh", such as Rajesh

Tutor's tip. The wildcard symbol is the one students most often mix up. Remember that % stands for many or none, and _ stands for exactly one. If the question says "names starting with S", use 'S%'. If it says "names of exactly four letters", use '____' with four underscores.

1.11 Database Relationships

Tables in an RDBMS are linked to each other through keys. The link is called a relationship, and there are three standard kinds.

One-to-one (1:1)

Each record in one table is associated with exactly one record in another. This is uncommon because it usually means the two tables could have been merged, but it is useful when a small part of the data is sensitive or rarely used and benefits from being kept separate.

Example: a Person and a Passport. Each person has at most one passport, and each passport belongs to one person.

One-to-many (1:M)

One record in the first table is associated with many records in the second, but each record in the second is associated with only one in the first. This is by far the most common relationship.

Example: a Teacher and Classes. One teacher may teach many classes, but each class is taught by one teacher.

Many-to-many (M:M)

Many records in one table are associated with many records in the other. This relationship cannot be stored directly in two tables; it requires a third table, called a junction table, which holds pairs of keys.

Example: Students and Courses. A student may enrol in many courses, and each course may have many students. A junction table Enrolments stores one row per student-course pair.

Concept cracker. Read the relationship in both directions. Start at the first table and ask "how many of the second can one of these touch?" Then start at the second and ask the same. If one-to-many both ways, the relationship is many-to-many. If many-to-one both ways, it is one-to-one.

1.12 MySQL Workbench and the Practical Workflow

MySQL Workbench is the graphical interface used to work with MySQL. It provides a place to write queries, see results in a grid and inspect the structure of tables. The workflow for any practical question follows the same order.

  1. Create the database with CREATE DATABASE.
  2. Select it with USE.
  3. Create the table with CREATE TABLE, specifying data types and constraints.
  4. Insert rows with INSERT INTO.
  5. Query, update or delete as the question requires.

Tutor's tip. If you run a query and get an error about an unknown database, you have forgotten USE. If you get an error about a table not existing, check spelling and capitalisation. SQL keywords are not case-sensitive, but table names are on some systems. Pick a convention, such as lowercase for tables and uppercase for keywords, and stay with it.

1.13 Reports in MySQL

A report is the organised presentation of data retrieved from one or more tables. In MySQL, a report is the result of a query, displayed in a way that helps a person understand or decide something.

Common types of reports include summary reports (totals such as total sales or number of students), detail reports (full lists of rows), grouped reports (rows grouped by category such as class or city), filtered reports (rows matching a condition, for example students above 80% marks) and aggregate reports (using functions such as SUM, AVG and COUNT).

MySQL itself produces raw structured data. For graphical or printable reports, it is connected to reporting tools such as Power BI, Tableau or Google Data Studio. The database does the storing and selecting; the reporting tool does the drawing.

1(a). Which of the following is an example of DBMS?

MS Word, MySQL, Photoshop, PowerPoint.

Answer — MySQL.

Reasoning: MS Word is a word processor, Photoshop is an image editor and PowerPoint is a presentation tool. None of them stores structured data with integrity rules and query support. MySQL is a database management system.

1(b). Data becomes information when:

It is raw and unorganized; it is processed and given context; it is stored in a table; it is in binary form.

Answer — It is processed and given context.

Reasoning: Raw facts become meaningful information only after processing that places them in a context, so that the reader can understand what they describe.

1(c). Which of the following is NOT a feature of DBMS?

Data redundancy; data integrity; data security; multi-user access.

Answer — Data redundancy.

Reasoning: Redundancy means unnecessary duplication of data, which a DBMS actively tries to reduce. Integrity, security and multi-user access are all features.

1(d). In SQL, which command is used to remove all records from a table but keep the structure?

DROP; DELETE; TRUNCATE; REMOVE.

Answer — TRUNCATE.

Reasoning: DROP removes the table itself. DELETE with no condition removes rows but is slower and can be rolled back. REMOVE is not an SQL command. TRUNCATE removes all rows in one operation and leaves the table structure intact.

1(e). The PRIMARY KEY ensures that:

Records are stored in order; each record is unique and not NULL; records can be duplicated; data can be stored in multiple tables.

Answer — Each record is unique and not NULL.

Reasoning: The purpose of a primary key is to identify each row uniquely, and it therefore cannot contain duplicate values or empty values.

1(f). Which of the following is a numeric data type?

VARCHAR; DATE; INT; TEXT.

Answer — INT.

Reasoning: INT stores whole numbers. VARCHAR and TEXT store text. DATE stores dates.

1(g). A field in one table that refers to the primary key in another table is called:

Candidate key; foreign key; composite key; super key.

Answer — Foreign key.

Reasoning: A foreign key is, by definition, a column in one table that points to the primary key of another table, creating a link between the two.

1(h). SQL stands for:

Structured Quick Language; Standard Query Language; Structured Query Language; Simple Query Language.

Answer — Structured Query Language.

1(i). In SQL, the % symbol is used in the LIKE clause to represent:

Single character; multiple characters; no character; NULL value.

Answer — Multiple characters.

Reasoning: % matches any sequence of characters, including none. The underscore _ matches exactly one character.

1(j). Which of the following is a DML command?

CREATE; SELECT; DROP; ALTER.

Answer — SELECT.

Reasoning: CREATE, DROP and ALTER are DDL commands because they change the structure. SELECT works on the data, so it belongs to DML.

1(k). What is the primary difference between CHAR(n) and VARCHAR(n) data types?

CHAR stores only numeric data, while VARCHAR stores text; CHAR has a fixed length, while VARCHAR has a variable length up to n characters; VARCHAR is used for dates, while CHAR is for text; there is no significant difference between them.

Reasoning: CHAR(n) always stores exactly n characters, padding with spaces when the value is shorter. VARCHAR(n) stores only the characters entered, up to n.

1(l). Which SQL data type is used for storing only date values (e.g., YYYY-MM-DD)?

Answer — DATE.

Reasoning: DATE stores only the date. TIME stores only the time. DATETIME and TIMESTAMP store both.

1(m). What does the SQL LIKE clause help you do?

Perform exact matches; search for patterns in data; sort the data; define data types.

Reasoning: The LIKE clause matches a column against a pattern using wildcards, rather than requiring the exact value.

Section 3 — Long Questions (5 Marks Each)

3(a). Explain the advantages and disadvantages of DBMS with suitable examples.

A Database Management System is software that sits between the user and the stored data, controlling how the data is stored, retrieved, changed and protected. Its benefits and costs are best understood through concrete cases.

Advantages.

  1. Reduced duplication. In a school, a student's name and address need be stored only once, in the Students table. Other tables refer to the student by ID. If the address changes, one update is enough. In a paper file system the same change must be made in every register, and any register missed becomes wrong.
  2. Consistency and integrity. A DBMS enforces rules. If marks are constrained to lie between 0 and 100, a typing error entering 1000 is rejected at the moment of entry. In a paper register the error would persist unnoticed.
  3. Fast retrieval. A library with fifty thousand books can find every book borrowed by a particular student in a fraction of a second. Doing the same manually would take hours.
  4. Security. Different users can be given different rights. A clerk may insert new students but not delete existing ones; a teacher may view marks but not change fees. The DBMS enforces these distinctions.
  5. Backup and recovery. Regular backups are built into the workflow. If a disk fails, the most recent backup restores the data. Without a DBMS, recovery depends on whether someone happened to make a copy.
  6. Concurrent use. Many clerks can work at the same time without overwriting each other's entries.

Disadvantages.

  1. Cost. Commercial DBMSs such as Oracle carry significant licensing costs, and even free systems incur hardware and training costs. A small shop may not recover these.
  2. Complexity. Designing tables, choosing data types and writing queries requires training. Mistakes in design are costly to undo once data has accumulated.
  3. Maintenance burden. Performance tuning, backup schedules and software updates are ongoing tasks. Neglect leads to slow queries or data loss.
  4. Single point of failure. If the central database goes down and backups are poor, the whole organisation loses access at once. A paper system degrades gradually; a centralised one can fail suddenly.
  5. Overkill for small needs. A single person keeping fifty addresses does not need a DBMS; a spreadsheet is simpler and adequate.

In summary, a DBMS is justified when data is large, shared, and valuable enough that errors and duplication carry real cost. For small, single-user tasks, its overhead outweighs its benefits.

3(b). Define different types of database relationships (1:1, 1:M, M:M) with examples.

A relationship in a database is a logical link between two tables, created by a foreign key in one table pointing to the primary key of the other. The type of the relationship describes how many rows in one table may be associated with how many rows in the other.

One-to-one (1:1). Each record in one table is associated with exactly one record in the other. This is uncommon because the two tables could usually be merged, but it is useful when one part of the data is sensitive or rarely used and benefits from separation.

Example: A Person table and a Passport table. Each person holds at most one passport, and each passport belongs to one person.

One-to-many (1:M). One record in the first table is associated with many records in the second, but each record in the second is associated with only one in the first. This is by far the most common relationship.

Example: A Teacher table and a Classes table. One teacher may teach several classes, but each class is taught by one teacher. The Classes table holds a TeacherID foreign key pointing to the Teacher table.

Many-to-many (M:M). Many records in one table are associated with many records in the other. This cannot be stored in two tables alone; a third table, called a junction table, holds pairs of keys.

Example: A Students table and a Courses table. A student may enrol in several courses, and a course may contain several students. A junction table, Enrolments, holds one row per student-course pair, with a foreign key to each of the other two tables.

3(c). Explain DDL and DML commands with examples.

SQL statements are grouped according to what they change. DDL changes the structure of the database; DML changes the data inside it.

DDL — Data Definition Language. DDL commands define or alter the shape of the database: which tables exist, what columns they have and what rules apply. They are committed automatically and cannot be rolled back.

CREATE TABLE students (
    ID INT PRIMARY KEY,
    Name VARCHAR(50),
    Class INT NOT NULL
);

ALTER TABLE students ADD Email VARCHAR(100);

ALTER TABLE students MODIFY Class INT DEFAULT 10;

DROP TABLE students;

Each statement changes structure. The first creates a table. The second adds a column. The third changes a column's default value. The fourth removes the table entirely.

DML — Data Manipulation Language. DML commands work on the rows inside a table. They can be rolled back if not committed.

INSERT INTO students (ID, Name, Class)
VALUES (101, 'Binay Adhikari', 10);

SELECT * FROM students WHERE Class = 10;

UPDATE students SET Class = 11 WHERE ID = 101;

DELETE FROM students WHERE ID = 103;

Each statement changes or reads rows. The first adds a row, the second reads rows, the third changes one row and the fourth removes a row.

In short, DDL is about the container; DML is about the contents.

3(d). What are database constraints? Explain NOT NULL, UNIQUE and CHECK with examples.

Constraints are rules attached to columns that restrict what values may be stored. They enforce data integrity by rejecting anything that violates the rule at the moment of entry, rather than allowing bad data to accumulate.

NOT NULL. The column must contain a value; empty values are rejected.

CREATE TABLE students (
    ID INT PRIMARY KEY,
    Name VARCHAR(50) NOT NULL,
    Class INT
);

Here Name cannot be left empty. Any attempt to insert a student without a name fails.

UNIQUE. Every value in the column must be different from all others. Unlike the primary key, more than one UNIQUE column may exist in a table, and a UNIQUE column may accept NULL in some databases.

CREATE TABLE employees (
    EmpID INT PRIMARY KEY,
    Email VARCHAR(100) UNIQUE
);

Here no two employees may share an email address, but the primary key is still EmpID.

CHECK. The column may only accept values that satisfy a condition.

CREATE TABLE marks (
    StudentID INT PRIMARY KEY,
    Score INT CHECK (Score BETWEEN 0 AND 100)
);

Here Score must lie between 0 and 100. An attempt to insert 150 is rejected.

Other constraints include PRIMARY KEY, FOREIGN KEY and DEFAULT. Together they enforce the business rules of the database at the data level.

3(e). Describe fields and records in a database with a neat example.

A database table is a grid of rows and columns. Each column is a field, and each row is a record.

A field is a column that holds one kind of fact for every record in the table. The field name describes what the column contains, and the field has a data type that determines what values are allowed.

A record is a row that holds one complete entry. It contains one value for each field.

Consider the following Students table.

StudentIDNameClassDateOfBirth
101Binay Adhikari102010-03-12
102Subigya Nepal102011-07-25
103Aarambha Gharti92013-11-10

The fields are StudentID, Name, Class and DateOfBirth. Each field holds one kind of value: StudentID holds whole numbers, Name holds text, DateOfBirth holds dates.

The records are the three rows. The row containing 101, Binay Adhikari, 10 and 2010-03-12 is one record, describing one student completely. There are three records and four fields in this table.

3(f). What is a Query? List out its importance in DBMS.

A query is a request sent to a database asking for data or asking for data to be changed. Queries are written in SQL.

Queries are important for several reasons.

  1. Selective retrieval. Instead of viewing an entire table, a query retrieves only the rows and columns that matter. A school can ask for the names of students in Class 10 whose fee is unpaid, and receive exactly those rows.
  2. Filtering and sorting. Queries can select rows matching a condition and order them by any field.
  3. Summary and analysis. Functions such as SUM, AVG and COUNT allow totals and averages to be computed directly within the database, without exporting data to another tool.
  4. Modification. Queries insert, update and delete rows, so all change to the data happens through the same controlled interface.
  5. Repeatability. The same query may be run again whenever needed, giving consistent results.
  6. Reporting. Reports of many kinds, from daily summaries to annual breakdowns, are built from queries.

3(g). In the context of MySQL, what is a report, and what is its purpose?

A report is the organised presentation of data retrieved from one or more tables, usually the result of a query, displayed in a format that helps a reader understand the data or make a decision.

MySQL itself produces structured data in tabular form. A report takes that structured output and presents it usefully: with column headings, in a chosen order, filtered to the relevant rows and often summarised. For graphical or printed reports, MySQL is connected to tools such as Power BI, Tableau or Google Data Studio.

The purpose of a report is to turn stored data into something a person can act on. A list of raw transactions is data; a monthly summary of sales by region is a report, and it is the report that guides decisions.

3(h). Describe Report with its features.

A report in MySQL is the output of one or more queries, arranged for reading and decision making.

Its features include the following.

  1. Organised data presentation. Columns are labelled and rows are arranged in a logical order.
  2. Data filtering. Only rows relevant to the question are included, using WHERE conditions.
  3. Summarisation. Totals, averages and counts are computed using aggregate functions, so the reader sees the whole picture rather than individual rows.
  4. Multi-table combination. Data from several tables is joined into a single view, so a report can show, for example, students together with the courses they have taken.
  5. Timely access. Reports are produced on demand, from current data, not from a snapshot taken weeks ago.
  6. Easy export. Report data can be exported to CSV, Excel or PDF and shared or printed.

Common types of report include summary reports showing totals, detail reports listing individual rows, grouped reports organising rows by category, filtered reports containing only rows that meet a condition and aggregate reports built entirely from functions such as SUM, AVG and COUNT.

Unit 2 — File Handling using Pandas

2.1 Why Files Exist

Everything a Python program works with lives in memory, and memory is cleared the moment the program ends. If the program is supposed to remember something after it closes, that something must be written to a file on the disk. A file is a named collection of data stored permanently on a storage device.

Writing data to a file and reading it back is called file handling. In Python, file handling is built into the language, and the Pandas library extends it to handle structured data such as CSV files with great convenience.

Concept cracker. Memory is a desk; the disk is a cupboard. Anything left on the desk disappears when you leave the room. Anything placed in the cupboard is still there tomorrow. File handling is the act of moving things between desk and cupboard.

2.2 Advantages and Disadvantages of File Handling

Advantages.

  • Data persists after the program ends.
  • Data can be shared between programs and between runs.
  • Python can work with many file types: plain text, CSV, binary and more.
  • The functions are simple and cross-platform, working the same on Windows, macOS and Linux.
  • Large quantities of data can be stored far beyond what memory would allow.

Disadvantages.

  • Code must be written carefully; a mistake in file handling can overwrite or corrupt data.
  • There are security risks, especially when file names come from user input.
  • Complex formats take more code to handle correctly.
  • Disk access is slower than memory access, so file-heavy programs can be slow.

2.3 Opening a File: The Modes

Before any file can be read or written, it must be opened. Python's built-in function open() does this. It takes two arguments: the name of the file and the mode.

file = open("data.txt", "r")

The mode decides what may be done with the file. There are four common modes.

ModeNameBehaviour
rReadOpens the file for reading. Raises an error if the file does not exist.
wWriteOpens the file for writing. Creates it if it does not exist. Erases existing contents if it does.
aAppendOpens the file for writing at the end. Creates it if it does not exist. Keeps existing contents.
xExclusive creationCreates a new file. Raises an error if a file of that name already exists.

Concept cracker. The letter tells you what the file is for: r for reading, w for wiping and writing, a for adding, x for a fresh file only. If you remember wiping for w, you will not accidentally destroy data by using the wrong mode.

Tutor's tip. Most beginner mistakes with files come from using w when a was intended. w erases the file's previous contents the moment it is opened, before a single character is written. If you wanted to add to an existing file, use a.

2.4 Closing a File, and the with Statement

Once a file has been opened and used, it should be closed. Closing frees system resources and ensures that any buffered data is flushed to the disk.

file = open("data.txt", "r")
content = file.read()
print(content)
file.close()

The with statement does the same work more safely. The file is closed automatically as soon as the block ends, even if an error occurs inside it.

with open("data.txt", "r") as file:
    content = file.read()
    print(content)

Tutor's tip. Learn the with statement as your default. It removes an entire class of bug, and it saves you from remembering to call close. Then, when a question asks specifically about close(), you still know what it does.

2.5 Reading from a File

Three methods read from a file.

MethodEffect
read()Reads the entire file as one string.
read(n)Reads the next n characters.
readline()Reads one line, up to and including the newline character.
readlines()Reads all lines into a list, one string per line.
with open("data.txt", "r") as file:
    first_line = file.readline()
    rest = file.read()
    print(first_line)
    print(rest)

2.6 Writing to a File

Two methods write to a file.

MethodEffect
write(s)Writes the string s to the file. Does not add a newline.
writelines(list)Writes each string in the list to the file. Does not add newlines.
with open("data.txt", "w") as file:
    file.write("First line\n")
    file.write("Second line\n")

Note the explicit \n at the end of each string. Without it, the two writes would appear on the same line.

lines = ["First line\n", "Second line\n", "Third line\n"]
with open("data.txt", "w") as file:
    file.writelines(lines)

Tutor's tip. Neither write nor writelines adds a newline automatically. Every newline must be placed by hand in the string. If your output comes out as one long line, the missing \n is the reason.

2.7 CSV Files and Why They Matter

A CSV file, standing for Comma Separated Values, stores tabular data as plain text. Each row of the table becomes one line of the file, and each column value within a row is separated from the next by a comma.

Name,Age,Grade
Binay,15,A
Subigya,14,B
Aurora,15,A

CSV files are favoured because they are plain text and therefore portable, simple to read and write, and supported by almost every language and spreadsheet program.

Concept cracker. A CSV file is a table that has been flattened into text. Every line is a row, and every comma marks a column boundary. If you can picture the table, you can picture the file.

2.8 Reading and Writing CSV Files with the csv Module

Python's standard library includes a csv module for reading and writing these files without Pandas.

import csv

with open("students.csv", "r") as csvfile:
    reader = csv.reader(csvfile)
    for row in reader:
        print(row)

Here csv.reader returns an object that yields one list per row. Each list contains the values of that row, separated by commas.

Writing is done with csv.writer and its writerow method.

import csv

with open("students.csv", "w", newline="") as csvfile:
    writer = csv.writer(csvfile)
    writer.writerow(["Name", "Age", "Grade"])
    writer.writerow(["Binay", 15, "A"])
    writer.writerow(["Subigya", 14, "B"])

The newline="" argument prevents blank lines appearing between rows on Windows.

2.9 Pandas and DataFrames

Pandas is a Python library built for data analysis. It is built on top of NumPy and offers a single object, the DataFrame, that holds a whole table in memory and supports reading, filtering, aggregating and writing with very little code.

A DataFrame is best thought of as a table with named columns, where each column is a series of values of one type.

To install Pandas if it is not already available:

pip install pandas

To use it in a program:

import pandas as pd

The alias pd is a widely followed convention and should be used.

2.10 Reading a CSV File with Pandas

The function pd.read_csv() reads a CSV file and returns a DataFrame.

import pandas as pd

df = pd.read_csv("students.csv")
print(df)

The result is printed as a table with an index on the left, one column per field.

      Name  Age Grade
0    Binay   15     A
1  Subigya   14     B
2   Aurora   15     A

The index 0, 1, 2 is generated automatically. It is not part of the data unless explicitly saved.

Common attributes and methods on a DataFrame include the following.

Attribute or methodEffect

2.11 Writing a CSV File with Pandas

To write a DataFrame to a CSV file, use to_csv().

import pandas as pd

data = {
    "Name": ["Binay", "Subigya", "Aurora"],
    "Age": [15, 14, 15],
    "Grade": ["A", "B", "A"]
}
df = pd.DataFrame(data)
df.to_csv("students.csv", index=False)

The argument index=False prevents Pandas from writing its internal row numbers as a column in the file. Almost every practical question expects index=False.

Tutor's tip. When you save a DataFrame and then read it back, forgetting index=False produces an extra unnamed column at the start. If you see a column called "Unnamed: 0" in the output, the file was saved without index=False.

Section 3 — Long Questions

3(a). Explain in detail the advantages and disadvantages of file handling in Python.

File handling is what makes a Python program able to remember. Without it, every run starts from nothing, and every result vanishes when the program closes.

Advantages.

  1. Persistence. Data written to a file survives after the program ends and after the computer restarts. A student's marks saved to a CSV file today are still there next week.
  2. Sharing. Files provide a natural way for programs to exchange data. One program writes a CSV; another reads it without knowing anything about the first.
  3. Capacity. Files can hold far more data than memory can. A program can read a large file in chunks and process it without loading everything at once.
  4. Format flexibility. Python handles text files, binary files, CSV files and more with the same core functions, and Pandas extends this to structured tabular data.
  5. Cross-platform. The same code works on Windows, macOS and Linux; the operating system's differences are handled by Python.

Disadvantages.

  1. Risk of data loss. Opening a file in 'w' mode erases its contents immediately. A single mistake in mode selection can destroy important data.
  2. Security concerns. If user input determines the filename, a malicious user may be able to read or overwrite files outside the intended scope.
  3. Complexity of formats. While CSV is simple, formats such as JSON, XML or binary structured files need careful parsing, and errors are easy to introduce.
  4. Slower than memory. Disk operations are far slower than in-memory operations. A program that reads a large file line by line will be much slower than one working entirely in memory.
  5. Error handling is needed. Files may not exist, may be locked, may have the wrong permissions, or may be corrupted. Every file operation must be written with these possibilities in mind.

For a small program that just needs to save a few values, the cost is minimal. For large systems with sensitive data, the disadvantages are real and require deliberate handling.
